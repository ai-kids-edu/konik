## #1 — Passenger quest state machine  (STRONG · fixes a live bug)

**Files/functions:** `assignNewPassengerQuest` 1405, `updateReturnQuests` 1433, `updatePassengerQuests` 1629,
`completePassengerDelivery` 1598, delivery branch in `handleSpaceAction` 5290–5333, global `ridingFarmer`.

**Problem.** One FSM (assign → mount → deliver → away-timer → return → home) smeared across 5 functions + the SPACE
handler. Delivery is implemented **twice**. The correct impl `completePassengerDelivery` (1598) has **zero callers** —
dead code. The only live path (`handleSpaceAction` 5319) forgets `farmer.awayAt`, skips `hideDestinationMarker()`,
ignores `isReturn`. **Live bug:** delivered townsfolk never get `awayAt`, so `updateReturnQuests` (guard `if(!f.awayAt)`
1437) never fires → they never ask to go home → the town empties.

**Solution.** One owner for delivery. Route the SPACE path through `completePassengerDelivery` (single delivery impl),
define the delivery radius once, group the FSM helpers under a `PassengerQuests` namespace object. Deletion test: yes —
kills the dead copy and the missing-`awayAt` bug becomes impossible.

**Wins:** locality (FSM in one place) · duplicated delivery collapses to one path · `awayAt` bug fixed · radius defined once.

## #2 — Difficulty rules into the LEVELS table  (STRONG · nearly pure)

**Files/functions:** `LEVELS` 5943, globals `level` 387 / `maxNumber` 388, `generateProblem` 4804,
`generateWrongAnswers` 4834, `updateDifficulty` 5953, dot-render gate in `createChallenge` 4704.

**Problem.** `maxNumber` is derived (`LEVELS[level-1].maxNum`) but stored separately and hand-synced in 4 places
(5960, 5968, 6212–6213). Per-level rules are inline magic thresholds at 6 sites: subtraction `maxNumber>=7` (4807),
visual dots `level<=3` (4812, 4704), sub-range cap (4822), wrong-answer floor `maxNumber>5` (4837), promote `level<=3?2:3` (5957).

**Solution.** `LEVELS` rows carry the behaviour (`maxNum, useVisual, canSubtract, subCap, allowZeroWrong, needed`).
Read rules off the current row; delete `maxNumber` as separate state (derive via a `currentRules()` accessor).
Deletion test: yes — every threshold concentrates into the table.

**Wins:** thresholds in one table · derived `maxNumber` deleted · pure arithmetic, testable without a scene.

## #3 — Player module (horse + stamina + jump)  (STRONG · seam)

**Files/functions:** globals 419–446 (`horsePos, horseAngle, horseSpeed, currentMaxSpeed, isJumping, jumpVy,
sprintUntil, stamina, isSprinting, runTimer, walkTime`), `attemptJump` 1710, `attemptEatHay` 1718,
`attemptDrinkWater` 1730, movement/stamina/jump integration in `update()` 5367–5488.

**Problem.** No player object — a dozen loose globals mutated by BOTH input handlers AND 100+ lines of `update()`.
Dead-but-load-bearing `sprintUntil` (432) duplicates `isSprinting`, re-synced every frame (5379), read once at 1767.
The perf refactor did **not** touch this.

**Solution (staged).** (a) Retire `sprintUntil`: read `isSprinting` at 1767, delete the global + the 5379 sync — one-line seam.
(b) Lift stamina drain/regen/consume into a small `Stamina`/`Player` surface (pure arithmetic over `stamina`/`MAX_STAMINA`)
that input handlers and the loop both call. Collision stays behind a `world.blocked(x,z)` seam.
Deletion test: `sprintUntil` deletes cleanly once 1767 reads the real flag.

**Wins:** stamina math in one place · sparkle hack retires · input + loop share one interface.

## #5 — Challenge factory (delete the dead duplicate)  (WORTH EXPLORING → now cheap)

**Files/functions:** `createChallenge` 4495, `createChallengeAt` 6069–6151.

**Problem.** `createChallengeAt` (~83 LOC) is a near-duplicate of `createChallenge` (carries the comment
"same code as createChallenge") that omits `problemData` → loses visual dots. It has **zero callers** (restore path
rewritten to always call `createChallenge`, 6242–6246). Pure dead-code + drift hazard.

**Solution.** Delete `createChallengeAt` outright. If any shared mesh-building is worth extracting, pull a
`buildBucket()` helper used by `createChallenge`. Deletion test: passes emphatically (no callers).

**Wins:** ~83 shallow LOC removed · one constructor owns the field contract.

## #6 — Economy module (buy/sell/afford)  (WORTH EXPLORING)

**Files/functions:** `SHOP_ITEMS` 366, `attemptBuyItem` 1666, zone tick 1186, buy prompt 1239, keydown map 4859.

**Problem.** Affordability re-derived in 3 places with differently-spelled predicates (1192, 1245/1259, 1675–1676).
`SHOP_ITEMS[*].key` (367–373) is dead parallel data — the keydown handler hardcodes the same mapping (4859–4864)
and never reads `.key`.

**Solution.** Add a `canBuy(itemKey)` predicate used by all three sites; drive the keydown buy map off `SHOP_ITEMS`
(read `.key`) so the parallel switch disappears. Deletion test: `.key` stops being dead once the switch derives from it.

**Wins:** one `canBuy` predicate, three callers · key map derives from `SHOP_ITEMS` · economic rules testable.
